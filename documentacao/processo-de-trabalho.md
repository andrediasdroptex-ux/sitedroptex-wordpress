# DROPTEX — Processo de Trabalho

## Objetivo

Garantir que toda alteração realizada no site seja organizada, documentada, rastreável e alinhada aos objetivos da DROPTEX.

---

# Objetivo da DROPTEX

A DROPTEX existe para:

* Gerar autoridade no mercado.
* Captar leads qualificados.
* Vender serviços logísticos.
* Vender produtos.
* Vender mentorias e treinamentos.
* Apresentar a plataforma DROPTEX.
* Converter visitantes em clientes.

---

# Regra Principal

Antes de qualquer alteração:

Analisar a estrutura existente.

Compreender:

* Objetivo da página.
* Objetivo da funcionalidade.
* Impacto da alteração.
* Dependências envolvidas.

---

# O que NÃO fazer

* Não recriar recursos existentes.
* Não apagar funcionalidades sem validação.
* Não alterar identidade visual sem necessidade.
* Não remover conteúdo importante.
* Não criar duplicidades.
* Não instalar plugins sem justificativa.

---

# O que DEVE ser feito

* Priorizar reaproveitamento.
* Documentar alterações relevantes.
* Manter organização das pastas.
* Utilizar GitHub para versionamento.
* Validar alterações antes de publicar.

---

# Fluxo de Alteração

1. Identificar necessidade.

2. Analisar estrutura atual.

3. Definir solução.

4. Registrar planejamento.

5. Executar alteração.

6. Testar funcionamento.

7. Registrar resultado.

8. Atualizar documentação.

9. Commitar alterações.

10. Enviar para GitHub.

# Uso de Inteligência Artificial

Antes de sugerir alterações, a IA deve:

1. Analisar documentação existente.

2. Entender o objetivo do negócio.

3. Explicar:

* O que será alterado.
* Motivo.
* Benefícios.
* Arquivos envolvidos.

4. Priorizar melhorias de:

* UX
* Conversão
* SEO
* Performance
* Responsividade

---

# Controle de Versão

Toda alteração relevante deve ser enviada ao GitHub.

Fluxo padrão:

git add .

git commit -m "Descrição da alteração"

git push

---

# Princípio da DROPTEX

Evoluir continuamente.

Melhorias pequenas e constantes geram resultados maiores do que grandes mudanças sem planejamento.
